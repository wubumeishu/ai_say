# 03 · 自动引流 / LINE 对接 / 私域管理

> 项目计划书章节（Ai SAY）——承接「消息翻译 + 推荐回复」能力，把每一次平台会话变成可留存的私域资产。

本章节目标：在不触发平台风控的前提下，把「平台私信客户」逐步沉淀为「LINE 自有客户」，并建立统一的客户画像与触达体系。

---

## 1. 设计总览

```
平台会话（FB/WhatsApp/…）
   │  消息抓取 + 翻译（现有能力）
   ▼
意向识别引擎 ──► 话术生成引擎 ──► 合规/频控闸门
   │                │
   ▼                ▼
平台内引导话术      发送「留 LINE」动作
   │
   ▼
客户留 LINE 号码 / 扫码加好友
   │
   ▼
LINE Messaging API / LINE Login
   │
   ▼
私域：统一客户档案（Unified Profile）+ 标签 + 触达策略
   │
   ▼
长期运营：再营销 / A/B 话术 / 风控监控
```

关键原则：

- **先私域，后成交**：平台私信只做「桥」，沉淀到 LINE 后再做深度沟通与复购。
- **合规优先**：所有自动发送必须经过频控与话术审核闸门；LINE 侧遵守官方 ToS，不做批量骚扰。
- **可回退**：任何一步失败（客户未留 LINE、加好友未通过）都停留在平台侧继续服务，不丢单。
- **数据统一**：平台客户与 LINE 客户通过手机号 / 平台 ID 双键绑定成统一档案。

## 2. 意向识别（Leads Scoring）

### 2.1 会话信号

| 信号 | 示例 | 权重 |
| --- | --- | --- |
| 回复速度 | 24h 内 ≥3 次回复、平均间隔 <10min | 高 |
| 关键词命中 | 价格 / 库存 / 交期 / 下单 / 样品 / "available?" / "how much" | 高 |
| 留 LINE 意愿 | 主动说 "add me on LINE"、留下 LINE ID、回复 "ok line" | 最高 |
| 询价深度 | 连续追问规格 / MOQ / 物流 / 发票 | 中高 |
| 沉默后再活跃 | 隔夜回复、主动发起话题 | 中 |
| 负面情绪 | 投诉、催单 | 中（需先安抚，再引流） |

### 2.2 评分模型

- 实现为轻量规则 + 加权分（0–100），不依赖大模型，便于线上调参与可解释性。
- 输出三档：**hot（≥80）/ warm（50–79）/ cold（<50）**。
- 触发阈值可配置（按窗口 / 平台 / 客户语言分别设参）。
- 每次评分落库：`session_id, platform, customer_id, score, signals[], ts`，作为话术 A/B 与漏斗分析的数据基础。

### 2.3 识别时机

- 实时：每条新消息入队即打分；
- 会话级：会话进入静默（>10min）时做最终判定，决定是否触发「留 LINE」引导。

## 3. 自动引流话术引擎

### 3.1 生成策略

- 模板库：按「品类 × 语言 × 意向档位 × 平台」组织的话术模板（如英语客户 hot 档：报价确认 → 交期 → 留 LINE 话术）。
- 变量填充：商品名 / 价格 / MOQ / 到货时间 等，从会话上下文自动抽取。
- 个性化增强（可选）：对 hot 客户用 LLM 生成个性化首句，模板兜底，保证语气与合规。
- 多语言：模板按目标客户语言渲染，内部统一中文管理界面。

### 3.2 引导到 LINE 的标准动作

1. 发出引导话术（示例）："For faster updates on your order, add us on LINE: `aisay.official` — I'll share tracking & samples there."
2. 平台侧同步留下联系方式卡片 / 链接（合规允许时）。
3. 客户留 LINE 后，记录 `platform_customer_id ↔ line_user_id ↔ phone` 三元组。
4. 30 分钟内未留 LINE → 发一条提醒话术（限 1 次）；仍未留 → 归档，不再自动跟进。

### 3.3 合规与频控（平台侧）

- 频控：同一客户 24h 内自动发送 ≤ 2 条；全局每分钟 ≤ N 条（按平台限制配置，默认 FB 私信 <10/min）。
- 话术审核：所有自动发送前过「关键词黑名单 + 模板版本校验」；黑名单词自动拦截。
- 人工闸门：hot 客户默认人工确认一次发送；cold 客户默认不自动发送，仅推荐回复。
- 记录：每次发送落库（客户、模板版本、时间、结果），支持审计与回滚。
- 平台 ToS：遵守 Facebook / WhatsApp / Instagram 各自对商业私信与引流的限制；优先用平台允许的「Profile 链接 / 个人主页」渠道引导，避免私信内硬广。

## 4. LINE 官方 API 对接（私域基建）

### 4.1 需要的官方产品

| 能力 | 官方 API | 用途 |
| --- | --- | --- |
| 双向消息 | LINE Messaging API | 收发消息、群发、标签推送 |
| 身份 | LINE Login | 客户用 LINE 一键确认身份，绑定手机号 |
| 加好友 | LINE 好友请求 | 客户扫码 / 加 LINE ID `aisay.official` 后自动进私域 |
| 客户群 | LINE Official Account（友达） | 粉丝群发、欢迎语、自动回复 |
| 数据 | Webhook（事件） | 加好友 / 消息 / 群组事件实时回调 |

### 4.2 核心链路

1. **加好友事件**：客户加 OA → Webhook `follow` 事件 → 立即发「欢迎语 + 身份确认」（问手机号或引导 LINE Login 授权）。
2. **身份绑定**：LINE Login 拿到 `openId / displayName`，客户填手机号 → 写回统一档案；未绑定手机号时以 `openId` 为主键。
3. **双向消息**：客户发 LINE 消息 → Webhook `message` → 进统一会话中心（与平台侧同一张 `session` 表，仅换 `channel='line'`）。
4. **客户标签群**：
   - 用 Messaging API 的 **Rich Menu + 标签**给 OA 友达打标签（`tag` 能力或自建标签表 + 按标签拉 `user` 列表做定向发送）；
   - 典型标签：`来源平台(FB/IG/…)、意向档(hot/warm)、品类、国家、已下单、VIP`；
   - 定向触达 = 拉该 tag 的 user 列表 → 批量 push（注意 4.4 限制）。
5. **群发与预算**：
   - 免费档 10K messages/月，按 10 美元/10K 计费的付费池；预算告警 80%。
   - 群发前必须过频控（见 4.4），避免一次性打满预算。

### 4.3 服务端组件

- `line-webhook`：收事件，幂等（event 去重），写入统一事件流；
- `line-client`：封装 sendReply / push / multi / webhook 校验（签名头 `x-line-signature` 必须校验）；
- `line-directory`：缓存 OA 的 user 列表与标签映射，避免每次 push 都全量拉；
- 安全：Channel Access Token 存 Key Vault，定期轮换；Webhook 只收 HTTPS。

### 4.4 频控与预算（LINE 侧）

- OA 对同一用户 24h 内主动 push ≤ 2 条（欢迎语 / 回复不计）；
- 群发分批：每批 ≤ 50 人、批间隔 ≥ 5s；
- 静默期：未互动 30 天的用户自动移出群发名单（降低无效消耗与封号风险）；
- 预算：月度池 + 单客户上限双层告警。

## 5. 私域管理：Unified Profile 与触达策略

### 5.1 Unified Profile（统一客户档案）

```
customer_profile
├─ keys: { platform: {fb: id, wa: jid}, line: {openId, userId}, phone, email }
├─ identity: { name, country, language, timezone }
├─ lifecycle: { first_seen, last_seen, stage: 潜客/询盘/成交/复购 }
├─ tags[]: 见 5.2
├─ score: { hot/warm/cold, computed_at }
└─ history: 统一 session 列表（平台 + LINE 同一张会话表）
```

- 绑定规则：`phone` 是首选 join key（LINE Login 提供）；无 phone 时 `platform_id ↔ line_userId` 手工绑定一次后永久生效。
- 冲突处理：同号多平台账号 → 同一 profile，保留各渠道 ID。
- 数据主权：遵循客户所在国隐私要求（GDPR / PDP 等），提供删除出口。

### 5.2 标签体系

| 层级 | 示例标签 | 来源 |
| --- | --- | --- |
| 来源 | `fb_page`、`ig_dm`、`wa_inbound`、`line_organic` | 渠道 |
| 意向 | `hot`、`warm`、`cold` | 意向引擎 |
| 品类 | `hardware`、`packaging`、`oem` | 会话抽取 |
| 状态 | `inquiry`、`quoted`、`paid`、`vip` | 业务事件 |
| 运营 | `no_reply_30d`、`sample_sent`、`blacklist` | 策略 |

- 标签自动打（规则引擎）+ 人工补（管理台）；变更全部审计。

### 5.3 触达策略

| 场景 | 渠道 | 频率 | 说明 |
| --- | --- | --- | --- |
| 欢迎 & 身份确认 | LINE | 1 次 | 加好友后立即 |
| 询价跟进 | LINE（未绑 phone 用平台侧） | 48h 内 1 次 | 未成交才发 |
| 上新 / 样品 | LINE 群发 | 月 ≤ 2 | 只发标签匹配用户 |
| 复购提醒 | LINE 群发 | 季度 ≤ 1 | 按成交品类 |
| 流失召回 | 平台 + LINE | 30/60/90 天各 1 次 | 三次未回自动停 |
| 黑名单 | 全渠道 | 停发 | 投诉 / 垃圾账号 |

- 所有触达走统一的「策略引擎」：按标签选人群 → 套模板 → 过频控闸门 → 发送 → 回收点击/回复/转化事件。

## 6. 风控

### 6.1 平台侧（防封号）

- 行为模拟：自动消息节奏模仿人工（随机 20–60s 间隔、按当地时区只在工作时段发）。
- 窗口级限流：单浏览器窗口 1 小时自动发送 ≤ 20 条，全局分钟级 cap；超限自动排队 + 告警。
- 新号养期：新平台账号 7 天内只发不自动收，人工白名单。
- 账号健康监控：抓取「被限流 / 被警告」信号（如 FB 提示 "your messages are limited"），触发即自动停发该账号 24h。
- 多账号隔离：每账号独立频控桶，禁止互借流量。

### 6.2 LINE 侧

- 严格按 4.4 频控；群发失败率 >5% 自动降速。
- OA 健康：官方 API 返回的封禁 / 受限状态纳入告警。
- 内容审核：群发前过敏感词库（金融 / 医疗 / 政治 / 赌博），命中即拦截并转人工。

### 6.3 话术 A/B

- 双版本：每个模板可挂 `variant_A / variant_B`，按客户随机 50/50 分流（同一客户固定一组，保证体验一致）。
- 指标：回复率、留 LINE 率、加好友通过率、7 日转化。
- 裁决：样本 ≥ 200/组后跑显著性检验（双比例 z 检验），胜者全量，败者归档；
- 全链路落库，支持按「平台 × 语言 × 意向档」分别看数。

### 6.4 数据与合规

- 客户数据加密存储，访问走 RBAC；
- 删除请求 30 天内全渠道清除（平台侧尽力、LINE 侧调用 delete user）；
- 每次自动发送保留 90 天审计日志。

## 7. 里程碑（对齐项目计划书）

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| M1（+2w） | 意向识别 + 平台侧引导话术（模板版） | 1 个窗口 hot 客户自动引导，不触发平台警告 |
| M2（+4w） | LINE OA + Webhook + 身份绑定 | 客户扫码 → 欢迎语 → 绑定手机号 全链路通 |
| M3（+6w） | Unified Profile + 标签 + 群发频控 | 定向群发 100 人，失败率 <5% |
| M4（+8w） | 触达策略引擎 + 话术 A/B | A/B 看板上线，可裁决胜出模板 |
| M5（+10w） | 风控全量（健康监控 / 养期 / 黑名单） | 连续 30 天 0 封号事件 |

## 8. 依赖与风险

- 依赖：LINE Official Account 开通（企业认证建议）、域名 / HTTPS Webhook、客户手机号采集授权文案。
- 主要风险：
  1. 平台升级私信风控 → 预留 24h 停发开关，话术可降级为「仅推荐、人工发」；
  2. LINE 免费额度不足 → 预算池告警 + 分档（VIP 客户优先）；
  3. 客户不给手机号 → 以 openId 为主键，转化路径改为「LINE 内报价成交」，不强依赖 phone。
