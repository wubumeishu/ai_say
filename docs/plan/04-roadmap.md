# 04 · 路线图 / 里程碑 / 验收标准 / 风险

> 本章是《Ai SAY 项目计划书》第四部分：分阶段里程碑（M0–M5）、各阶段可验收标准、团队分工（architect / engine / adapter / acquisition / ui）、风险清单与缓解、度量指标。
> 现状基线：比特浏览器窗口监控 + DevTools 消息翻译/推荐回复（已上线 0.1.0），资料页抓取脚本已验证（17098 窗口，见 [docs/tools/profile_17098_fields.md](../tools/profile_17098_fields.md)），消息列表扫描器（queueScanner）与资料画像（profileInspector）已完成原型，数据仍为 JSON 文件存储。

## 1. 分阶段里程碑

总体节奏：**M0 打地基（数据）→ M1 看懂客户（画像）→ M2 多平台（聚合）→ M3 自动引流（闭环）→ M4 LINE 私域（沉淀）→ M5 控制台（运营面）**。每阶段以"可验收标准"为出口条件，未达标不进入下一阶段。

### M0 数据模型重构

**目标**：把散落在 `data/*.json`（account-profiles / conversations / contacts）的文件存储，升级为可查询、可去重、可追溯的数据层，为画像与聚合提供统一实体模型。

**主要工作**
- 定义核心实体：`Account`（平台账号）、`Contact`（客户，跨窗口去重后的画像载体）、`Conversation`（会话）、`Message`（消息原文/译文）、`LeadEvent`（引流事件）、`LineMember`（LINE 私域成员）
- 统一主键：客户以 `platform + windowId + contactKey` 三元组暂存，跨平台靠"归一化姓名 + 手机号/画像特征"建立候选去重键（M2 再合并）
- 存储选型：本地 SQLite（better-sqlite3 或 node:sqlite），保留 JSON 导出/导入兼容现有脚本
- 字段画像结构对齐 `docs/tools/profile_17098_fields.md` 已验证的分组（基本/详细/兴趣/成人交友）
- 迁移：现有 JSON 数据一次性导入 + 可回滚

**可验收标准**
1. 现有 `data/` 三个 JSON 文件 100% 导入 SQLite，无字段丢失，可再导出为等价 JSON。
2. 同一客户跨窗口/跨页面重复出现在 `contacts` 中时，系统能按去重键合并且保留 `firstSeen / lastSeen` 时间戳。
3. 画像字段写入走统一的 `upsertContactProfile`，并发写不产生半写/损坏文件（现有 JSON 写盘竞态消除）。
4. 所有实体带 `createdAt / updatedAt`，并附一次"破坏性测试"（kill 服务重启后数据完整）。

### M1 自动画像

**目标**：把 17098 窗口已验证的"页面记录"（click_mypage / profile / show_profile 脚本）产品化为**自动画像引擎**，按 01 章 §3.5 / 02 章 §2.0 的固定顺序执行——**第一步资料页优先建立基础画像（昵称/年龄/地区/兴趣/交友状态等页面可观测字段），第二步聊天消息流补充细节（意图/历史偏好/回复习惯），聊天口误不覆盖页面真值**；不再依赖人工脚本。

**主要工作**
- 画像抽取器抽象：按"精确文本匹配 → 优先 href 跳转 → 回退 .click()"的已验证规则（见 [docs/tools/click_mypage_17098.md](../tools/click_mypage_17098.md)）实现通用导航器
- 字段级解析（第一步·资料页优先）：昵称、年龄、地区、身高、类型、交友状态、兴趣、见面期望等自动入库（对应 M0 `Contact` 画像），标记 `source=profile_page`，置信度最高
- 意图识别（第二步·聊天补充）：结合 aiService（LLM）从最近 5–10 条消息中抽取客户意图标签（交友/约会/引流线索/闲聊），标记 `source=chat`，只补资料页未覆盖字段；与页面字段冲突时按 02 章 §3.2 置信度规则取高值（页面真值优先）
- 自动补全建议：缺失画像字段（如未填的兴趣）由引擎标记为 `gap`，供 M3 话术利用（"你还没填兴趣，我们先聊 XX"）

**可验收标准**
1. 对 17098 窗口新会话，不运行任何人工脚本，系统 60s 内产出该客户画像（≥10 个字段）并入库。
2. 已验证页面的画像准确率 ≥ 90%（抽样 20 个会话，与人工核对）；资料页字段（`source=profile_page`）入库率 100%——凡可抓到资料页的客户，基础画像必须先于聊天细节入库（两步顺序不颠倒）。
3. 意图标签覆盖 100% 新会话（允许"闲聊"兜底标签，不允许空值）；聊天补充字段不得覆盖已入库的资料页字段（冲突时页面真值胜出，抽样 20 条验证 0 次降级）。
4. 旧版脚本标记 `deprecated` 但保留；自动路径与脚本路径对同会话输出字段一致率 ≥ 95%。

### M2 跨平台聚合

**目标**：支持 Facebook / WhatsApp / Telegram / LINE 等平台的**统一消息与画像模型**，一个客户多平台出现时聚合为同一人。

**主要工作**
- 平台适配器接口（adapter 角色）：`scanMessages / scanProfile / navigate / send` 四方法契约，平台差异全部收敛在适配器内
- 各平台实现：优先复用比特浏览器 DevTools 通道；DOM 定位按"精确文本 + href 优先"规则逐平台验证（沿用 17098 经验）
- 客户聚合：去重键升级为"姓名归一化 + 手机号 + 画像相似度（姓名/地区/年龄三元组）"，输出 `Contact.mergedFrom[]` 溯源
- 多窗口会话调度：sessionPool 支持跨平台并发窗口，互不串扰

**可验收标准**
1. 至少 3 个平台（现有出会/Pappy/イククル + Facebook + WhatsApp 中任选）跑通"消息监控 + 画像"全链路。
2. 已知同一客户在 2 个平台出现时，系统自动合并为 1 个 `Contact`，溯源字段完整。
3. 跨平台去重：20 条人工标注样本，误并率 ≤ 5%，漏并率 ≤ 10%（指标见 §4）。
4. 新增 1 个平台的适配工作量 ≤ 1 人·天（契约文档 + 定位规则）。

### M3 自动引流

**目标**：从"推荐回复给人看"升级为**自动引流闭环**：识别引流线索意图 → 自动发送话术 → 引导到 LINE/关注/跳转。

**主要工作**
- 引流规则引擎：意图 × 平台 × 话术模板匹配（常用语库迁入结构化模板）
- 自动发送通道：经 DevTools 在聊天输入框注入并发送（含图片/文字），遵守每会话冷却与频控
- 风控前置：单账号日发送上限、随机间隔、平台敏感词预检（与风险 R3 联动）
- 引流事件追踪：每次触发的 `LeadEvent`（谁、何时、哪条话术、客户响应）入库，M4 承接

**可验收标准**
1. 对标注为"引流线索"的会话，自动话术触发率 ≥ 90%，且 100% 有 `LeadEvent` 记录。
2. 24h 内客户对引流话术的正向响应率（回复/点击/加 LINE 任一项）作为 M4 输入基线（目标 ≥ 20%，不强制本阶段达标）。
3. 封号演练：频控上限生效，模拟超限被拦截并告警，无误发。
4. 话术模板可后台增改（为 M5 控制台预留接口）。

### M4 LINE 私域

**目标**：把引来的客户沉淀到 LINE 官方通道，建立私域资产与 1v1 自动化（LINE Official Account）。

**主要工作**
- LINE Official Account 接入：消息 webhook、profile 拉取、好友管理（走 LINE 官方 API，**不碰个人号**——见风险 R2）
- 客户迁移：`LeadEvent` 中已加 LINE 的客户自动绑定 `LineMember`，与 M0 `Contact` 双向关联
- 私域分层：按画像与互动频次打标签（新客/活跃/沉默/高意向）
- 自动化：欢迎语、标签化欢迎流、沉默客户唤醒（频控独立于 M3）

**可验收标准**
1. 官方 OA 审核通过且 webhook 稳定接收率 ≥ 99%（7 天统计）。
2. M3 引流成功的客户 100% 能在 24h 内自动匹配到 LINE 好友记录（按手机号/昵称匹配 + 人工兜底入口）。
3. 标签体系覆盖 ≥ 5 类客户状态，标签自动更新准确率 ≥ 85%。
4. LINE 侧封禁/拒接事件可观测（有日志与告警）。

### M5 控制台

**目标**：统一的运营 Web 控制台，把 M0–M4 的能力变成"看得见、改得动"的界面。

**主要工作**
- 现有 8300 控制台扩展为多页面：客户列表（画像聚合视图）、会话监控、引流看板（M3 指标）、LINE 私域看板（M4 指标）、规则/话术编辑、日志与审计
- 权限与审计：操作留痕（谁在何时改了什么规则/话术）
- 批量操作：批量补画像、批量唤醒沉默客户、导出/回滚
- 健康面板：各平台适配器心跳、DOM 变化告警（联动风险 R1）

**可验收标准**
1. 运营人员全程无需命令行即可完成：看客户画像 → 改话术 → 看引流/LINE 指标 → 审计日志。
2. 控制台核心页首屏 ≤ 2s（本地），指标数据延迟 ≤ 1min。
3. 规则/话术修改即时生效且可一键回滚到上一版本。
4. 平台 DOM 异常（定位命中率骤降）在面板内有告警卡片（联动 R1 监控）。

## 2. 团队分工（五角色）

> 角色是"职责切面"而非固定人头，可按人兼任，但每个阶段必须有唯一 owner。

| 角色 | 负责模块 | 主要产出 | 依赖 |
| --- | --- | --- | --- |
| **architect** | M0 数据模型与实体设计、去重键策略、M2 客户聚合算法、M4 绑定策略 | 数据字典、迁移脚本、聚合/去重逻辑、存储接口 | 无上游（M0 起点）；M2 聚合依赖 M1 画像质量 |
| **engine** | M1 自动画像引擎、M3 引流规则引擎、aiService（LLM 意图识别/推荐） | 画像抽取器、意图标签、规则匹配与话术注入、频控 | 依赖 M0 实体；M3 依赖 M1 意图标签与 M2 适配器 `send` |
| **adapter** | M2 平台适配器（Facebook/WhatsApp/Telegram/出会系）、导航规则（精确文本+href 优先）、DevTools 通道 | 各平台 `scanMessages/scanProfile/navigate/send` 实现、定位规则文档 | 依赖 M0 契约稳定；与 engine 的自动化路径联调 |
| **acquisition** | M3 自动引流话术库与规则、M4 LINE OA 接入与私域自动化、客户标签体系 | 话术模板、频控策略、OA webhook、标签/分层逻辑 | 依赖 M2（多平台来源）、M0（LeadEvent 实体）；LINE 审核周期需提前 4 周启动 |
| **ui** | M5 控制台、各阶段运营视图（画像详情、引流看板、LINE 看板、审计与回滚）、告警卡片 | Web 控制台页面、指标展示、编辑/回滚交互 | 依赖 M0–M4 全部 API；指标定义需与度量指标（§4）对齐 |

**关键协作边界**
- engine ↔ adapter：自动化动作一律走 adapter 契约，engine 不直接写 DOM。
- acquisition ↔ architect：LINE 绑定（手机号/昵称匹配）的规则由 architect 定键，acquisition 做运营流。
- ui 每阶段末介入一次"可展示性评审"，避免 M5 大爆炸式补课。

| R4 | **数据隐私**：抓取客户个人画像（年龄、地区、收入区间等）涉及个人数据合规 | M0–M5 全程 | 中 | ① 数据仅本地存储（SQLite 本地文件），不上传第三方；② 字段最小化：只存引流必需的字段；③ 导出/操作留审计日志（M5）；④ 明确平台 ToS 边界——**仅自动化平台已允许的用户自身操作**，不做爬虫式全站抓取；⑤ 涉及客户画像的字段在控制台默认脱敏展示 |
| R5 | LLM 依赖（aiService）不稳定/成本 | M1/M3 | 中 | ① 翻译已有 MyMemory→LLM 降级链路，扩展为多级降级；② 意图识别失败兜底"闲聊"标签，不阻塞主流程；③ 调用量看板 + 预算告警 |
| R6 | 多窗口 DevTools 并发资源 | M2/M5 | 低 | sessionPool 限并发窗口数；资源告警；单窗口故障不拖垮全局 |

## 4. 度量指标

> 四个核心指标对应四个阶段，每阶段验收与 M5 看板均以此为准。所有指标在 SQLite 中按日聚合，控制台展示 7 日/30 日趋势。

| 指标 | 定义 | 统计口径 | 目标值 | 对应阶段 |
| --- | --- | --- | --- | --- |
| **自动处理覆盖率** | 新会话中被自动化流水线（监控→画像→意图→话术/回复）处理占全部新会话的比例 | 自动完成画像≥10字段且产生至少 1 次自动回复或引流决策的会话 / 全部新会话 | M1 ≥ 80%；M3 ≥ 95% | M1/M3 |
| **引流成功率** | 引流动作达成目标的比例。分两层：① 触发成功率 = 话术实际发出 ÷ 决策触发数；② 转化成功率 = 客户产生正向响应（回复/点击/加 LINE 任一）÷ 话术发出数 | 按日 + 按话术模板 + 按平台 | 触发成功率 ≥ 99%；转化成功率 ≥ 20%（M3 基线，M4 起按月复评上调） | M3 |
| **LINE 转化率** | 来自自动引流的客户中，成功沉淀为 LINE OA 好友且完成标签绑定的比例 | 已绑定 LineMember 客户 ÷ M3 转化成功客户 | M4 验收 ≥ 60% | M4 |
| **去重准确率** | 客户跨窗口/跨平台合并的正确性。误并率 = 不同客户被合并为 1 个 ÷ 合并总数；漏并率 = 同一客户未合并 ÷ 应合并总数 | 抽样 ≥ 20 条人工标注 + 每月全量抽检 | 误并率 ≤ 5%，漏并率 ≤ 10%（M2 起持续监测） | M2/M4 |

**配套辅助指标**（进 M5 健康面板，不设硬目标）
- 平台定位命中率（R1 监控）：各适配器定位成功次数 ÷ 尝试次数，任一平台 7 日均值下降 > 20% 触发告警。
- 画像字段完整度：≥10 字段会话占比（自动处理覆盖率的前置）。
- LLM 调用成本/失败率（R5）。
- 单账号日发送量与风控拦截次数（R3）。

## 5. 里程碑总览

| 里程碑 | 出口条件（摘要） | 主要角色 | 前置 |
| --- | --- | --- | --- |
| M0 数据模型重构 | JSON 全量可逆迁移；去重键合并带时间戳；并发写安全 | architect | — |
| M1 自动画像 | 新会话 60s 自动画像 ≥10 字段（**资料页优先建基础画像，聊天补细节**）；准确率 ≥90%；意图无空值 | engine + adapter | M0 |
| M2 跨平台聚合 | ≥3 平台全链路；已知同客 2 平台自动合并；去重误并 ≤5% | adapter + architect | M1 |
| M3 自动引流 | 话术触发率 ≥90%；LeadEvent 100% 记录；封号演练通过 | engine + acquisition | M2 |
| M4 LINE 私域 | OA 审核通过；引流客户 100% 绑定 LineMember；标签准确率 ≥85% | acquisition + architect | M3 |
| M5 控制台 | 运营全程免命令行；指标延迟 ≤1min；可回滚；DOM 告警卡片 | ui + 全角色 | M0–M4 |
